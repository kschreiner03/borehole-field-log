# 3D plume Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** Smooth, labelled plume shells in the 3D view from MODFLOW 6 or from measured results, plus a cut-away along the section line.
**Spec:** `docs/superpowers/specs/2026-11-02-3d-plume-design.md`

## Global Constraints
- Labels:
  - model: "Model (MODFLOW 6), not measured" in `PLUME_RAMP.model`;
  - interpreted: "Interpreted from measured results, not modelled" in `PLUME_RAMP.meas`.
- Levels come from `plumeLevels('groundwater', param)`.

## Review Focus
1. A project with no guideline for the parameter: no shells, and the legend says why.
2. A single well with results: interpreted shells stay within 5 m of it.
3. All non-detects: no shells.
4. Rebuilding (exaggeration change, cut slider) does not leak geometry or GPU memory.
5. No WebGL or no three.js: the page still explains itself.

### Task 1: Field and isosurface
- [ ] Test "3d: surface nets and the measured plume field":
  - `isoSurface` on a sphere field gives vertices within 0.6 cells of the radius;
  - `plumeField3d` from the measured results:
    - equals the measured value at a well's screen middle (within 1 % in log);
    - is 0 more than 5 m beyond the wells' outline;
    - returns `src: 'interpreted'`.
- [ ] Implement `gwConcField(date, param)` (shared with `gwConcSampler`), `plumeField3d(list, date, param)` → `{ at(E,N,z), src, date, bbox }`, and `isoSurface(grid, level)` → `{ positions, indices }`. Commit.

### Task 2: Shells, labels, fading and the automatic model run
- [ ] Test "3d: plume shells":
  - without a run: `S.v3d.plume.src === 'interpreted'`, at least one mesh named `plume-1x` with vertices, and a legend reading "Interpreted from measured results";
  - with the mf6 preload, after transport has been saved: going to the 3D page runs the model by itself, then `src === 'mf6'` and the legend names MODFLOW 6;
  - ground opacity is ≤ 0.15 while shells show.
- [ ] Implement it in `v3dBuild`; `gwRefresh` rebuilds on `v3d`. Commit.

### Task 3: Cut-away
- [ ] Test "3d: cut along the section line":
  - ticking `#v3d-cut` sets one renderer clipping plane and adds a `cut-face` mesh;
  - moving `#v3d-cutpos` changes the plane constant;
  - unticking removes both.
- [ ] Implement it, then the full suite, review and merge.
